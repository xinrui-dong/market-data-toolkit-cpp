# 行情数据工具使用说明

这个 C++17 程序完成一条完整的数据处理流程：

~~~text
读 CSV → 检查日期和价格 → 计算收益率与 SMA → 写结果 CSV
~~~

## 先看一个能手算的例子

输入文件 data/sample_prices.csv 是明确标注的合成数据：

| 日期 | 收盘价 |
|---|---:|
| 2026-10-01 | 100 |
| 2026-10-02 | 110 |
| 2026-10-03 | 99 |
| 2026-10-04 | 108 |

收益率按“本条价格 ÷ 上条价格 - 1”计算：

- 第二条：110 / 100 - 1 = 0.1，即上涨 10%。
- 第三条：99 / 110 - 1 = -0.1，即下跌 10%。
- 第四条：108 / 99 - 1 = 1/11，约上涨 9.09%。

第一条没有前一个价格，收益率留空。这里计算的是相邻记录间的价格变化；若日期有间隔，不能直接叫每日收益率。

SMA 是窗口内价格的简单平均。窗口为 3 条记录时：

- 第三个位置：(100 + 110 + 99) / 3 = 103。
- 第四个位置：(110 + 99 + 108) / 3 = 317/3，约 105.6667。

前两条凑不齐 3 个价格，SMA 留空。这两个空值不是 0。

## 实际运行

在终端进入项目文件夹后执行：

~~~sh
bash scripts/verify.sh
./build/bin/market_data --input data/sample_prices.csv --window 3 --output build/analysis.csv
~~~

结果在 build/analysis.csv。CSV 可能显示 `0.10000000000000009` 这样的长小数，这是 double 不能精确表示部分十进制数造成的舍入，不是把 10% 算错。输出保留足够位数，便于重新读取同一个 double；阅读时可按需要显示成百分比。

不写 --output，就直接在终端输出 CSV：

~~~sh
./build/bin/market_data --input data/sample_prices.csv --window 3 --algorithm naive
./build/bin/market_data --input data/sample_prices.csv --window 3 --algorithm rolling
~~~

两种算法使用相同的输入和输出定义。默认是 rolling。--help 查看参数；不需要先安装额外的测试或测速库。

## 为什么需要两种算法

朴素算法把每个窗口重新加一遍。上面的两个窗口都用了 110 和 99，计算存在重复。

滚动算法保留当前窗口的和。第一个窗口和为 309；移动一次时：

~~~text
309 - 100 + 108 = 317
317 / 3 = 105.666666...
~~~

也就是减去离开的价格，加上新进来的价格。一般来说，朴素算法工作量随“记录数 × 窗口长度”增长，滚动算法的总工作量随记录数增长。

上面的减旧加新是数学上的等式。直接用 double 做“大数减大数”，可能丢失后来只剩下的小价格。因此最终代码用**两个栈组成的聚合队列**保存窗口，避免直接减去旧的大价格。

可以把栈想成一摞盘子：后栈接收新价格，前栈负责移走最旧价格；前栈空时，将后栈倒过来转入前栈。每一层同时保存这一段价格的补偿和。移走旧价格时，只弹出一层，剩余价格的和已经保存在下一层，不必从巨大总和里相减。

在例子里，旧的 100 离开后，前半段保留 110+99=209；后半段接收 108，两段相加得到 317，平均值仍为 317/3。

每个价格最多经历一次进入、一次转移和一次移除，所以总工作量仍是 O(n)，但要额外保存 O(window) 的窗口状态。某一次转移会处理整个窗口，因此不是每一步都严格 O(1)。补偿累加和这种结构改善数值稳定性，不保证任意 double 输入都精确。

## 程序会拒绝什么

- 日期写错、日期重复或顺序倒置。
- 价格缺失、无法完整解析、有尾随垃圾，或不是有限正数。
- CSV 缺列、多列、引号字段、空记录；本版只支持明确约定的两列格式。
- 窗口为 0、负数、非整数或超过记录数。
- 极端输入导致中间计算或结果变成无穷等非有限值。
- 输入文件与输出文件是同一个文件。

程序会给出原因，CSV 错误通常包含行号，并返回非零退出码。它不会偷偷排序、删掉坏行或补价格。文件先读完、校验和计算都成功，才打开输出文件，避免坏数据产生看似成功的结果；输出写入本身发生 I/O 错误仍会报错。

输入里的周末、假期或日期间隔不会自动被认定为错误。真实数据必须保持单一资产、币种和价格口径；本程序不执行复权，也不把价格收益率自动当作包含股息的总收益率。

## 怎样理解性能结果

运行 cmake --build build --target run_benchmarks 后，终端和 build/benchmark.json 会记录实际结果。

每种算法测 3 种数据规模和 3 种窗口，一共 18 个配置，每个配置重复 3 次。输入生成与文件读写不计入算法测速；两个算法都计入参数验证和结果向量分配。比较时必须看同一个 n 和 window，不能拿一个小输入和另一个大输入比较。

window=1 时两个算法本来都接近复制数据，不应期待明显加速。较大窗口时，减少重复求和才可能带来优势。CPU 负载和机器差异也会改变耗时，复杂度不等于某个固定加速倍数。

本机 2026-10-14 的一次 Release 测量中，65,536 条价格、窗口 100 时，CPU 耗时中位数从朴素算法的 28.998 毫秒降到滚动算法的 1.248136 毫秒，约为 23.23 倍。窗口 1 时两者几乎相同。完整的 9 组配对结果、原始测量快照和测量条件见 [性能结果](benchmark-results.md)；换机器或重跑，数字会变化。
